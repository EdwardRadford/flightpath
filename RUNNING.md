# Running FlightPath locally

How to get the FlightPath Flutter app booting in an Android emulator from a fresh
clone.

The convenience script is PowerShell, so the scripted path is Windows-only. Every
step it automates can be done by hand on macOS or Linux — the `flutter run`
invocation it builds is given below. iOS builds need a Mac and are not covered
here.

## Prerequisites

1. **Flutter SDK** `^3.6.0`, matching `pubspec.yaml`, on PATH.
   - https://docs.flutter.dev/get-started/install
   - Check with `flutter --version`.
2. **Android Studio** with at least one AVD created.
   - More Actions → Virtual Device Manager → Create Device. Any Pixel profile on
     API 34 is fine.
3. **`flutter doctor`** showing no red X against "Android toolchain" or
   "Android Studio".

Firebase config is committed (`android/app/google-services.json`,
`lib/firebase_options.dart`). These files hold client identifiers, which are public
by design; they are generated by FlutterFire and should not be hand-edited.

## First run

From the repo root:

```powershell
flutter pub get
copy tool\.env.local.example tool\.env.local
```

`tool/.env.local` holds RevenueCat SDK keys. It can stay blank — the run script
supplies placeholder `--dart-define` values for anything missing, and the app boots
in free-tier mode with them. The file is gitignored; `tool/.env.local.example`
documents the keys it can hold.

## Running

### PowerShell script

```powershell
.\tool\run-emulator.ps1
```

It checks `flutter` is on PATH, loads `tool/.env.local` if present, finds a running
device or launches the first AVD it can see (waiting up to 90s for it to come
online), then runs `flutter run --debug` with the right `--dart-define` flags.

Flags:

| Flag | Effect |
|---|---|
| `-Profile` | profile build |
| `-Release` | release build, signed with the debug key |
| `-Emulator "Pixel_7_API_34"` | pick a specific AVD |
| `-NoLaunchEmulator` | fail rather than auto-start an AVD |

### VS Code

With an emulator already running, press F5 and pick
**"FlightPath - Android emulator (debug)"**. The configurations are committed in
`.vscode/launch.json`; profile and release variants are there too. Hot reload works
as normal.

If you have real RevenueCat keys, either use the PowerShell script — which reads
`tool/.env.local` automatically — or replace the placeholder values in
`.vscode/launch.json`'s `toolArgs` locally.

### By hand, on any platform

```bash
flutter run --debug \
  --dart-define=REVENUECAT_ANDROID_KEY=goog_dev_placeholder \
  --dart-define=REVENUECAT_IOS_KEY=appl_dev_placeholder
```

Hot reload is `r` in the terminal running `flutter run`.

## Dart-defines the app reads

| Flag | Required | Source | Placeholder |
|---|---|---|---|
| `REVENUECAT_ANDROID_KEY` | yes — a debug build throws `StateError` when it is empty | `tool/.env.local` | `goog_dev_placeholder` |
| `REVENUECAT_IOS_KEY` | no on Android | `tool/.env.local` | `appl_dev_placeholder` |

Both are read with `String.fromEnvironment` in
`lib/shared/services/subscription_service.dart`. The debug build fails loudly on a
completely empty `REVENUECAT_ANDROID_KEY`, which is why the script always passes at
least the placeholder. With the placeholder, `Purchases.configure` fails, init
retries three times, and the app continues in free-tier mode: paywall screens
render but list no offerings.

## Troubleshooting

**"flutter is not on PATH"** — add the Flutter SDK's `bin` directory to PATH and
restart your shell or editor.

**"No Android AVDs found"** — create one in Android Studio's Virtual Device
Manager (any Pixel profile, API 34), then re-run.

**"Emulator did not come online within 90 seconds"** — start the AVD from Android
Studio, wait for the home screen, then re-run `.\tool\run-emulator.ps1`.

**"StateError: RevenueCat SDK key missing"** — `tool/.env.local` sets
`REVENUECAT_ANDROID_KEY=` with no value *and* the placeholder is not being applied.
Check you are invoking the script rather than bare `flutter run`; if you are, look
for the "Loading env" line in its output, because a malformed line in
`tool/.env.local` can clobber the fallback. Commenting the line out with `#` is the
quickest fix.

**Firebase errors at boot** — confirm `android/app/google-services.json` and
`lib/firebase_options.dart` are present, then `flutter clean && flutter pub get`
and retry.

**Slow first build** — the first `flutter run` on a fresh clone pulls Gradle and
the Android build tools. 5-10 minutes is normal; later runs take seconds.

## Things not to do

- Do not commit `tool/.env.local`.
- Do not hand-edit `lib/firebase_options.dart`, `google-services.json` or
  `GoogleService-Info.plist`. FlutterFire generates them.
- Do not distribute a release build made this way. Release signing is not
  configured in this repo, so `-Release` produces a debug-signed APK that is only
  good for local smoke-testing. A Play Store bundle needs a real keystore.
